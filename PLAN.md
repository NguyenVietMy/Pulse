## Context

The eval harness already exists and is further along than it looks:

- `api/src/test/java/com/pulse/pulse/evals/ResumeScoringEvalTest.java` — 100+ fixtures with
  expected score ranges/decisions, plus an LLM groundedness judge (`AnthropicService.judgeGroundedness`,
  claude-sonnet-5). Tagged `evals`, excluded from `mvn test` via surefire; an `evals` Maven profile runs them.
  Requires `ANTHROPIC_API_KEY` in the environment.
- Fixtures in `api/src/test/resources/evals/resumes/` are **synthetic** (generated by
  `ResumeFixtureGenerator`) — no human labels yet.
- Evals do NOT run in CI (`.github/workflows/deploy-api.yml` runs plain `mvn test`).
- `PulseObservability` (Micrometer/Prometheus) is wired into `AnthropicService`, but the API
  response `usage` field is discarded — no token/cost tracking.
- **Provider switch (2026-07-10):** all chat/scoring ops moved from OpenAI to the Anthropic Java SDK
  (`AnthropicService`, formerly `OpenAiService`; metrics renamed `pulse.openai.*` → `pulse.ai.*`).
  Model assignments: resume scoring + eval judge = `claude-sonnet-5`, all cheap ops (digest,
  insights, daily tasks, roadmap, memory, chat, event/section tasks) = `claude-haiku-4-5`.
  Scoring-cache hash now includes the model, so old GPT-scored cache entries are invalidated.
- **Embeddings stay on OpenAI** (`EmbeddingService`, `text-embedding-3-small`, 1536-dim pgvector) —
  Anthropic has no embeddings API. Requires a small OpenAI credit top-up (~$5 lasts years at
  $0.02/1M tokens). Both `OPENAI_API_KEY` (embeddings) and `ANTHROPIC_API_KEY` (everything else)
  are required.

## Decisions (locked in 2026-07-10)

| Decision | Choice |
|---|---|
| Human labeling scope | 40–50 fixtures, hand-labeled by Viet via a local HTML labeling UI (score range, decision, judge-verdict grading); 2 scoring runs per fixture to observe variance |
| CI gate design | Golden subset (~25 of the labeled fixtures) with pass-rate threshold in `deploy-api.yml` test job; full 100+ suite stays manual/nightly |
| Tracing | Langfuse Cloud free tier, via OTel GenAI-semconv traces to Langfuse's OTLP endpoint (no Java SDK exists); redact/truncate resume text in traces |
| Routing | Eval-validated tiering: per-operation configurable models, use eval harness to find cheapest scoring config that holds pass rate. NOT confidence-based escalation. |
| Provider (2026-07-10) | Anthropic for all chat/scoring/eval ops (OpenAI credits exhausted). Scorer + judge: `claude-sonnet-5`. Cheap ops: `claude-haiku-4-5`. Embeddings stay OpenAI. Phase 2.4 becomes an Anthropic tier sweep (Sonnet 5 vs Haiku 4.5 for scoring; Opus 4.8 as quality-ceiling reference). |

## Phase 1 — Evals as infrastructure (do first; Phase 2's routing needs this gate as referee)

- [ ] **1.1 Labeling harness.** Script/test that runs ~30 stratified fixtures (across
      intern/junior/mid/senior + tags), captures model scores + judge verdicts, and emits a
      human-review sheet (JSON or Markdown).
- [ ] **1.2 Human labeling (manual, Viet, ~3–4 hrs).** For each fixture: confirm/correct expected
      score range + decision; grade each judge groundedness verdict as correct/incorrect.
      Commit labels as golden fixtures (e.g. `evals/resumes/golden/` manifest with `humanLabels` block).
- [ ] **1.3 Judge alignment metric.** Compute judge↔human agreement (accuracy + Cohen's kappa)
      from the labels. If agreement is weak, iterate on the judge prompt and re-measure.
- [ ] **1.4 CI regression gate.** Step in `deploy-api.yml` test job running the golden manifest
      via the `evals` profile; fail (blocking deploy) if pass rate < threshold (start at 90%).
      Requires `ANTHROPIC_API_KEY` in GitHub Actions secrets. NOTE: smoke test measured ~40s per
      fixture on Sonnet 5 (adaptive thinking) — 25 fixtures sequential ≈ 17 min. Enable JUnit
      parallel execution (`junit.jupiter.execution.parallel.*`) for the gate to bring it to ~3-4 min.
- [ ] **1.5 Verify the gate.** On a branch, intentionally break the scoring prompt → gate must
      fail; revert → gate passes.

## Phase 2 — Cost + observability

- [ ] **2.1 Token/cost capture.** In `executeChatCompletion`, stop discarding `usage`; emit
      Micrometer counters (input/output tokens + dollar cost from a pricing table), tagged by
      `operation` and `model`, through the existing Prometheus export.
- [x] **2.2 Langfuse tracing.** Export OTel traces (GenAI semantic conventions) from the existing
      Micrometer Observation setup to Langfuse Cloud's OTLP endpoint. Redact/truncate resume text.
      Landed via issue 09. Spans carry no prompt/completion bodies at all, verified by fetching
      6 traces back through `langfuse-cli`. Issue 10 extended the same treatment to `agent/` and
      joined the two into one trace per chat, Java → Python → node → Anthropic. **2.1 is now
      trivial:** `AnthropicService.recordUsage`
      already reads `usage.inputTokens()`/`outputTokens()` — 2.1 is just emitting those as
      Micrometer counters. Note Langfuse already computes dollar cost server-side, so the pricing
      table 2.1 calls for is only needed for the Prometheus path. **Live in production since issue
      11** (`environment=dev`): the first prod chat trace costed at $0.006771 across three Haiku 4.5
      generations, so 2.4's before/after can be read off real traffic, not just local runs.
- [ ] **2.3 Model config.** Make the model per-operation configurable (properties-driven) instead
      of hard-coded constants in `AnthropicService`. (The digest 3.5-turbo→cheap-tier win landed
      already as part of the provider switch: digest now runs on Haiku 4.5.)
- [ ] **2.4 Eval-validated routing experiment.** Run the golden suite with scoring on cheaper/
      pricier configs (`claude-haiku-4-5` vs `claude-sonnet-5` vs `claude-opus-4-8` reference);
      pick the cheapest that holds the pass-rate threshold. Record before/after cost from 2.1
      metrics — this is the measured % for the resume.
